# 직접 입력·OCR·선택적 AI 정산 — 엄격 검토 수정본

사용자가 제출한 네 파일의 세 가지 입력 탭, 품목 수정 표, 복사 기능을 활용했습니다.
결제자/분담 방식 추정, 빈 금액의 0원 변환, 총액 임의 보정, 확인 체크 자동 선택을 제거했습니다.
이 폴더는 앞서 준비한 FastAPI/HTML/SQLite 통합본에 연결해 검증한 전체 프로젝트입니다.
사용자의 PC나 GitHub 저장소를 직접 변경한 것은 아닙니다.

## 적용할 파일

기존 프로젝트에서 아래 여섯 파일은 같은 버전으로 함께 적용하세요.

1. `src/settlements/receipt_fields.py` — 교체: OCR 후보만 추출. 총액 충돌/누락 시 미정 유지.
2. `src/settlements/receipt_draft.py` — 추가: 엄격한 금액/이름 검증, 정산 입력·확인 근거 생성.
3. `src/settlements/receipt_api.py` — 교체: 수동 정산, 검수 저장, 선택적 AI, 수정 버전 검사.
4. `src/settlements/workflow_store.py` — 교체: 영수증과 정산을 같은 DB 트랜잭션으로 저장.
5. `frontend/receipt.html` — 교체: 품목/금액 표, 별도 결제자·검수자, 명시적인 분담 선택, 복사.
6. `frontend/index.html` — 교체: 세 입력 방식, 확인 체크 초기화, 결제자 추정 제거, AI 연결.

`receipt_api.py`만 교체하고 `workflow_store.py`를 빠뜨리면 connection 인자 오류가 날 수 있습니다.
`app.py`에는 `receipt_router` 등록이 필요합니다. 포함된 루트 `app.py`가 검증한 기준 버전입니다.
팀원의 CLI `workflow.py`에는 웹 라우터를 추가하지 않습니다.
`COPY_FULL_CODE.txt`에는 여섯 파일의 전체 코드가 파일명별로 들어 있습니다.
각 FILE 구분선은 설명이므로 Python/HTML 파일 내용으로 붙여넣지 마세요.
`review-changes.diff`는 제출한 네 파일과 이전 저장 모듈을 기준으로 만든 비교 자료입니다.

이 폴더를 기존 프로젝트와 별도 위치에 풀어 실행하면 다른 버전의 파일이 섞이는 문제를 피할 수 있습니다.
기존 소스에 옮길 때는 본인의 최신 변경과 비교하고 여섯 파일 및 필요한 app.py 연결을 반영하세요.

## 실행

이 폴더의 `app.py`가 보이는 위치에서 PowerShell을 엽니다.
이미 설치한 가상환경을 쓴다면 `python`이 그 가상환경을 가리키는지 확인하세요.
새 환경이 필요할 때만 첫 두 줄을 실행합니다.

```powershell
python -m venv .venv-ocr
.\.venv-ocr\Scripts\Activate.ps1
python -m pip install -r requirements-ocr.txt
```

실제 OCR를 쓰려면 PaddlePaddle CPU도 필요합니다. 이미 설치했다면 다시 설치하지 않아도 됩니다.

```powershell
python -m pip install paddlepaddle==3.3.0 -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
python -c "import paddle; paddle.utils.run_check()"
```

실행 정책 때문에 Activate.ps1이 막히면 이후 명령의 `python`을
`.\.venv-ocr\Scripts\python.exe`로 바꿔 실행하세요. 실행 정책 변경은 필요하지 않습니다.

기존의 유효한 GEMINI_API_KEY, GEMINI_MODEL 설정을 이 폴더의 `.env`에 둡니다.
직접 입력과 OCR 수동 정산에는 Gemini 호출이 없습니다.
PaddleOCR SDK는 실제 사진 인식 시에만 불러옵니다. 최초 실행은 모델 다운로드가 필요합니다.

```powershell
$env:PYTHONPATH = "src"
python -m uvicorn app:app --host 127.0.0.1 --port 8000 --workers 1
```

브라우저: http://127.0.0.1:8000
영수증 화면: http://127.0.0.1:8000/receipts/new

로컬 단일 서버 프로세스용입니다. 로그인/공개 배포/프로젝트 전체 API 할당량 관리는 포함하지 않습니다.
은행 송금이나 메시지 발송은 실행하지 않습니다.

## 경로별 동작

- 직접 입력: 명시한 결제자·분담 대상자·금액·균등 분담 선택 → 초안 → 확인 → Python 계산.
- OCR: 사진 → 후보 표 → 사람 수정 → `/draft` → 초안. Gemini 호출 없음.
- OCR에서 AI로: 검수 저장 `/review` → AI 입력창. 이 이동에는 Gemini 호출 없음.
  사용자가 AI 적용을 누른 경우에만 `/ai`에서 저장된 검수 근거와 추가 조건을 전송.
- 텍스트만 AI: 기존 일반 문장 API 사용. 영수증은 필수가 아님.
- `/session`은 이전 클라이언트용 호환 경로입니다. 신규 화면에서는 `/draft`, `/review`, `/ai`를 사용합니다.
  호환 경로의 기존 기본 동작은 유지되므로 신규 요청에 사용하지 마세요.

분담 대상과 결제자는 별도입니다. 결제자가 분담 대상에 없다면 돈을 먼저 낸 사람으로만 등록합니다.
검수 담당자의 이름을 결제자로 사용하지 않습니다.
분담 방법이나 결제자가 미정인 초안도 보관할 수 있지만, 보완하기 전에는 확인/계산할 수 없습니다.

실제 결제 총액과 영수증에 표시된 총액은 별도입니다. 하나를 고쳐도 다른 값을 자동으로 덮어쓰지 않습니다.
빈 금액은 null(미정), 0원은 0입니다. 소수/음수/불리언/잘못된 쉼표 형식은 임의 보정하지 않습니다.
OCR의 품목 합계를 영수증 총액으로 대신 채우지 않습니다.
할인/환불/외화/복잡한 열 구조/여러 총액 등은 자동 해결하지 않고 검수할 줄로 남깁니다.
'7번가피자'처럼 이름에 포함된 숫자를 제거하지 않습니다.
단가·수량·항목 금액이 여러 열인 경우 인식한 열 제목으로 금액 열을 구분할 때만 자동 입력합니다.
영수증 레이아웃 전체를 지원하는 범용 추출기나 학습 모델을 새로 만든 것은 아닙니다.

현재 범위는 영수증 한 장 → 정산 초안 하나입니다. 여러 영수증 병합은 포함하지 않습니다.
정산에 연결한 영수증을 바꾸려면 연결한 정산에서 조건을 수정하거나 별도 영수증 초안으로 시작하세요.

## 발견한 주요 결함

- receipt_fields.py의 전역 변수 앞 들여쓰기 때문에 모듈 import가 실패함.
- 금액이 없는 경우 품목 합계를 원본 총액처럼 채워 넣음.
- 서로 다른 총액 후보 중 마지막 값만 선택해 충돌이 사라짐.
- 현금 결제금액, 0원, 콜론/두 줄 총액을 누락하며 이름 앞 숫자를 지움.
- 첫 참여자 또는 '총무'를 결제자로 추정함.
- 결제자와 검수자를 같은 인물로 취급하고 외부 결제자를 자동 부담자로 추가함.
- 미정 분담 방법을 equal로 확정함.
- 빈칸/잘못된 숫자를 0원으로 바꾸거나 행을 누락함.
- 사용자의 확인 체크와 찬조금 확인을 자동으로 켬.
- 영수증 수정 후 확인 체크가 유지됨.
- AI 전달 후 원본 연결/검수 버전 추적이 끊기고 오래된 sessionStorage 값이 섞일 수 있음.
- 영수증과 정산 저장이 분리돼 저장 장애/동시 요청에서 일관성이 깨질 수 있음.
- 다른 창에서 정산 조건이 바뀐 뒤에도 이전 계산 결과를 복사할 수 있음.
