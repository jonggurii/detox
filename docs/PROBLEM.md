# 문제 정의서

## 왜 만드는가

**1. 한 문장 문제**

모임의 정산 담당자는 개인별 소비·참여 시점·찬조금 등 서로 다른 분담 조건을 반영하고 지출·청구·입금 기록을 맞추기 위해 여러 도구에서 계산과 대조를 반복하며, 그 과정에서 중복·누락 확인과 정산 근거 설명·재요청에 추가 시간과 부담을 들인다.

**2. 대상과 비대상**

- 1차 사용자: 최근 1개월 이내 모임·여행 등에서 지출을 취합하고, 개인별 부담액 산정·정산 안내·입금 확인을 직접 담당한 사람. 특히 소비 항목·참여 시점·찬조금 등의 차이를 반영해야 하는 정산 담당자

- 비대상: 정산을 관리하지 않고 안내받은 금액만 송금하는 참여자. 다만 내역 확인·안내 수신의 대상에는 포함. ( 비대상 업무 : 기업의 공식 회계·세무·경비 승인, 판매대금 관리, 전문적인 채권 회수 업무 )

**3. 증거**

인터뷰 프로토콜과 Job Story는 [research/interviews_union.md](research/interviews_union.md)에 있다. 아래 로그 번호는 인터뷰 원자료의 증거 식별자를 보존한다.

- 개인별·혼합 분담의 수기 계산 : 편의점 구입 물품의 가격 차이가 커 개인별 금액을 따로 계산했고, 균등 분할과 차액 정산이 섞였을 때 번거로움을 겪었다. 술값 추가 부담을 반영하기 위해 메모장에 개인별 금액을 따로 조합하기도 했다. ( 로그 6, 7, 20 )

- 중복·누락 추적 부담 : 정산 건수가 늘어나자 이미 올린 정산인지, 빠진 정산이 없는지 기존 내역을 반복 확인했다. ( 로그 2, 4 )

- 잘못된 비용 포함과 이의 제기 : 중도 이탈한 사람에게 이탈 후 추가 주문한 술값까지 청구했고, 당사자가 이의를 제기하여 별도의 설명·조율이 발생했다. ( 로그 15 )

- 실제 입금과 완료 표시의 불일치 : 별도 계좌이체를 확인한 뒤 정산 서비스에서 수동으로 완료 표시를 했으며, 실제 입금을 확인하지 못해 완료 표시가 빠진 경험이 있었다. ( 로그 14 )

- 복잡한 분담 조건의 조율 : 팀장 찬조금 5만 원을 공제하고, 맥주 한 잔만 마시고 이탈한 참여자의 부담액을 별도로 조율했다. ( 로그 15, 18 )

- 정산 이후의 설명·재요청 작업 → 설명 공간이 부족해 상세 내역을 추가 메시지로 작성했고, 송금이 늦은 사람에게 따로 연락하거나 송금 가능한 시점에 계좌와 금액을 다시 안내했다. ( 로그 11, 13, 16 )

**4. 반증 조건**

문제의 존재와 해결 방식의 효과를 구분하여 판단한다. 아래 수치는 검증 전에 확정할 기준의 제안이며, 현재까지 달성한 결과를 뜻하지 않는다.

- 문제의 실재 (인터뷰 증거로 지금 판정)

  - 주장: 개인별 소비·참여 시점·찬조금 등 서로 다른 분담 조건을 반영하는 정산 담당자는 부담액 산정과 지출·청구·입금 기록 관리 과정에서 반복 계산·대조 및 설명·조율 부담을 겪는다.

  - 반증 조건: 최근 1개월 이내 위 조건이 포함된 정산을 직접 담당한 서로 다른 사용자 10명의 실제 사례를 확인한다. 다음 중 하나 이상으로 추가 작업이 발생한 사람이 3명 미만이면, 현재 대상 집단에 대한 핵심 문제 가설을 지지하기 어렵다고 판단하고 대상 또는 문제의 범위를 수정한다.

    + 개인별 조건을 반영하기 위해 금액을 여러 번 계산하거나 수정했다.
    + 중복·누락 또는 입금 상태를 확인하기 위해 정산 내역을 반복 대조했다.
    + 중복·누락 또는 입금 상태를 확인하기 위해 정산 내역을 반복 대조했다.

    재요청 대상·시점·문구를 따로 관리한 행동은 후속 관리 부담의 증거로 별도 집계한다. 이를 계산·검증 부담과 구분하여 어떤 문제를 우선 해결할지 판단한다.

  - 현재 판정: 기존 로그에서 해당 문제의 구체적 사례는 확인된다. 다만 로그 20개는 서로 다른 사용자 20명을 의미하지 않는다. 응답자별로 중복을 제거하고 대상 조건과 경험 시점을 확인해야 하며, 현재 자료만으로 위의 10명 기준을 충족했다고 판정하지 않는다.

- 해결 가설 (제품 사용 관찰로 이후 판정)
  - 가설: 사용자가 확인한 분담 조건에 따른 개인별 부담액·산출 근거와 청구·입금 확인 정보를 연결해 제공하면, 정산 담당자가 동일한 정보를 여러 도구에 재작성하고 반복 계산·대조하는 작업과 실제 작업 시간을 줄일 수 있다.

  - 반증 조건: 사용자가 합의한 조건과 일치하는 금액·근거가 제공되고 입금 확인 및 재요청 정보도 정상적으로 기록되는 상황에서, 관찰 대상 10명 중 5명 이상이 여전히 별도 메모장·계산기·엑셀에 동일한 정산 내역을 다시 만들고 그 자료를 기준으로 정산을 진행한다면 해결 가설을 기각하거나 수정한다. 단, 잘못 계산된 금액이나 누락된 항목 때문에 외부 도구를 사용한 사례는 계산·입력 품질 문제로 따로 기록한다. 은행 앱의 실제 입금 확인과 메신저의 안내 전송은 현재 제품 범위에서 필요한 외부 작업이므로, 해당 앱을 사용했다는 사실만으로 실패로 판정하지 않는다. 다만 그 과정에서 발생하는 작업 시간과 재입력은 전체 작업량에 포함한다.

**5. 성공의 정의**

- 첫 정산 요청까지의 전환율(활성화) : 복합 정산 입력을 시작한 사용자 중, 분담 조건과 산출 근거를 확인하고 참여자에게 정산 안내를 전달한 사용자의 비율을 측정한다.

- 확인된 분담 조건에 맞는 정산 : 사용자가 확인한 조건에 따라 개인별 부담액과 송금 요청 금액이 산출되고, 잘못된 대상에게 청구하거나 동일 내역을 중복 청구하지 않는다. 청구액 합계·결제자 본인 부담액·확정 찬조금 적용액을 합한 값이 결제 총액과 일치하며, 금액의 근거를 확인할 수 있다.

- 반복 작업의 감소 : 비슷한 복잡도의 정산을 기존 방식과 비교했을 때, 별도 계산·명단 대조·동일 내역 재작성 횟수와 실제 작업 시간이 줄어드는 정도를 측정한다. 측정에는 제품 내부의 입력·수정·검토와 외부 도구 사용 시간을 포함하되, 상대방의 송금을 기다리는 시간은 제외한다.

- 실제 입금과 일치하는 상태 관리 : 담당자가 실제 입금 내역을 대조하여 청구별 확인 상태를 갱신하고, 필요한 경우 재안내를 관리하며 정산을 마무리하는지 확인한다. 관찰 기간 안에 종료 여부를 확인할 수 있는 모임을 대상으로, 계산·청구 누락 없이 모든 유효 청구를 확인하고 완료까지 기록한 비율을 측정한다. 아직 입금 대기 중인 모임은 진행 중으로 구분한다.

-	다음 복합 정산에서의 재사용률 : 첫 사용 이후 다시 복합 정산을 맡을 기회가 생긴 사용자 중, 다음 모임에서도 제품을 사용한 사용자의 비율을 측정한다.
