# 문제 정의서

## 왜 만드는가

**1. 한 문장 문제**

복합 모임의 정산을 맡은 대학생과 직장인이, 개인별 소비·참여 시점·찬조금에 따른 부담액과 청구·입금 상태를 일관되게 파악하지 못해 반복 계산과 대조에 시간을 쓰고, 정산 근거 설명과 송금 재요청 과정에서 관계 부담을 겪는다.

**2. 대상과 비대상(검토 필요)**

- 1차 사용자: 최근 1개월 이내 2차 이상의 모임에서 직접 정산을 담당한 대학생과 직장인. 특히 품목별 소비 차이, 중도 합류·이탈, 찬조금 등의 조건 때문에 개인별 부담액을 다르게 계산하고 입금 상태까지 확인해야 하는 사람.

- 비대상: 동일한 금액의 단순 N분의 1 정산을 기존 도구로 충분히 처리하는 사람, 정산 내역을 관리하지 않고 안내받은 금액만 송금하는 일반 참여자, 기업의 공식 회계·세무·경비 처리가 필요한 담당자.

**3. 증거**

인터뷰 프로토콜과 Job Story는 [research/interviews_union.md](research/interviews_union.md)에 있다. 아래 로그 번호는 인터뷰 원자료의 증거 식별자를 보존한다.

- 개인별 소비와 예외 조건에 따른 수기 계산 부담 : 균등 분할과 차액 정산이 섞이면 계산이 번거로웠고, 비주류자·중도 이탈자·찬조금을 반영하기 위해 금액을 따로 계산하거나 조율했다.
( “특히 N분의 1 정산과 차액 정산이 섞여 있는 정산을 할 때 매우 번거로웠어요.” — 로그 5,6,7,17,18,20 )

- 정산 내역의 중복·누락을 반복 확인하는 부담 : 지출과 정산 건수가 늘어나면서 이미 청구한 내역과 남은 내역을 계속 대조했다. ( “혹시 중복해서 올린 건 아닌지, 누락된 정산은 없는지를 추적하다보니 확인할 많아졌어요.” - 로그 4 )

- 실제 입금과 정산 완료 표시를 맞추는 부담 : 별도 계좌이체를 받은 뒤 기존 정산 서비스에서 완료를 수동으로 표시했으며, 입금 확인을 놓쳐 완료 처리가 누락된 경험이 있었다. ( 로그 14, 관찰 1 )

- 비용 분담 근거를 설명하고 조율하는 부담 : 중도 이탈 이후 주문한 술값이 포함되어 이의가 제기됐고, 복잡한 산출 근거를 설명하기 위해 별도 메시지를 작성했다. ( 로그 12,15,16 )

- 송금 재요청과 관계를 고려한 표현의 부담 : 미입금자에게 기다렸다가 개인 연락을 보내거나 상대의 송금 가능 시점을 고려해 다시 안내했다. 재요청할 때는 유쾌하거나 정중한 말투를 선택하며 표현을 조정했다. ( 로그 11,13,17,18,20. )

- 문제의 범위를 제한하는 경계 증거 : 단순 균등 분할은 기존 도구로 처리할 수 있었고, 기존 서비스의 자동 알림으로 개인 재요청을 생략한 사례도 있었다. 또한 소액을 정밀하게 회수하기보다 무시하거나 대신 부담하기도 했다. 따라서 모든 정산에 새 도구나 독촉이 필요하다고 가정하지 않는다. ( 로그 8,9,10,19 )

**4. 반증 조건**

문제의 존재와 해결 방식의 효과를 구분하여 판단한다. 아래 수치는 검증 전에 확정할 기준의 제안이며, 현재까지 달성한 결과를 뜻하지 않는다.

- 문제의 실재 (인터뷰 증거로 지금 판정)

  - 주장: 복합 모임의 정산 담당자는 개인별 부담액과 청구·입금 상태를 관리하면서 반복 계산·대조 또는 설명·재요청 작업의 부담을 겪는다.

  - 반증 조건: 대상 조건을 충족하는 서로 다른 사용자 10명 중, 최근 1개월의 실제 정산에서 다음 중 하나 이상을 경험한 사람이 3명 미만이면 현재 문제 정의를 기각하고 대상 또는 핵심 문제를 다시 정한다.

    + 개인별 조건을 반영하기 위해 금액을 여러 번 계산하거나 수정했다.
    + 중복·누락 또는 입금 상태를 확인하기 위해 정산 내역을 반복 대조했다.
    + 잘못 포함된 비용을 설명·조율하거나, 재요청 대상·시점·문구를 별도로 관리했다.

  - 현재 판정: 기존 로그에서 해당 문제의 구체적 사례는 확인된다. 다만 로그 20개는 서로 다른 사용자 20명을 의미하지 않는다. 응답자별로 중복을 제거하고 대상 조건과 경험 시점을 확인해야 하며, 현재 자료만으로 위의 10명 기준을 충족했다고 판정하지 않는다.

- 해결 가설 (제품 사용 관찰로 이후 판정)
  - 가설: 사용자가 확인한 분담 조건을 바탕으로 개인별 금액과 산출 근거를 제공하고, 청구·입금 확인·재요청 정보를 연결하면 별도 계산과 명단 대조를 줄이면서 정산을 마무리할 수 있다.

  - 반증 조건: 사용자가 합의한 조건과 일치하는 금액·근거가 제공되고 입금 확인 및 재요청 정보도 정상적으로 기록되는 상황에서, 관찰 대상 10명 중 5명 이상이 여전히 별도 메모장·계산기·엑셀에 동일한 정산 내역을 다시 만들고 그 자료를 기준으로 정산을 진행한다면 해결 가설을 기각하거나 수정한다. 단, 잘못 계산된 금액이나 누락된 항목 때문에 외부 도구를 사용한 사례는 계산·입력 품질 문제로 따로 기록한다. 은행 앱에서 실제 입금을 확인하거나 카카오톡으로 안내를 보내는 행위도 현재 제품 범위에서 필요한 외부 작업이므로, 그 자체를 가설 실패로 세지 않는다.

**5. 성공의 정의**

- 첫 정산 요청까지의 전환율(활성화) : 복합 정산 입력을 시작한 사용자 중, 분담 조건과 산출 근거를 확인하고 참여자에게 정산 안내를 전달한 사용자의 비율.

- 반복 작업의 감소 : 비슷한 복잡도의 정산을 기존 방식과 비교했을 때, 별도 계산·명단 대조·동일 내역 재작성 횟수와 실제 작업 시간이 줄어드는 정도. 송금을 기다리는 시간은 작업 시간에서 제외한다.

- 정산 상태 관리의 지속 사용 : 정산을 요청한 모임 중, 담당자가 실제 입금 내역을 확인한 뒤 청구별 상태를 갱신하고 필요한 재요청을 관리하여 완료까지 기록한 모임의 비율.

- 다음 복합 정산에서의 재사용률 : 첫 사용 이후 다시 복합 정산을 맡을 기회가 생긴 사용자 중, 새 모임에서도 제품을 사용한 사용자의 비율.
