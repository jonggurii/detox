# 복합 모임 정산 온톨로지 — 쉬운 용어와 정의

상세 개념 모델은 [ontology.yaml](ontology.yaml)에 있다. 두 파일은 같은 한글 대표 용어를 사용한다. 영문 이전 이름은 기존 스펙·API·코드를 연결하기 위한 대조표다. 한글 키로 이름을 바꿨으므로 기존 영문 키를 쓰는 구현 문서는 별도 이관이 필요하다.

인터뷰의 문제·행동을 개념과 관계로 표현한 모델이다. 클래스 분리·식별자·상태·계산 순서 자체가 인터뷰로 검증되었다는 뜻은 아니다. 각 개념의 `evidence`는 대응하는 문제의 출처를 가리킨다.

## 1. 클래스 용어 정의

| 대표 용어 | 뜻 | 이전 영문명 |
|---|---|---|
| **참여자** | 이 모임 정산에 연결된 사람. 비용 부담자·결제자·담당자·찬조자 역할을 맡을 수 있다. | `Participant` |
| **모임 정산** | 한 모임이나 여행의 결제 내역, 비용 나누기, 송금 요청, 입금 확인을 묶는 전체 단위. | `SettlementSession` |
| **모임 차수** | 1차 식사·2차 술자리처럼 참석자와 결제 내역을 구분하는 자리. | `SettlementRound` |
| **차수별 참석 기록** | 특정 사람이 어느 차수에 어떻게 참석했는지 남긴 기록. 중간 합류·이탈도 기록한다. | `RoundParticipation` |
| **결제 내역** | 한 사람이 먼저 결제한 하나의 비용 기록. 영수증이 없어도 기록할 수 있다. | `Expense` |
| **찬조금** | 특정 결제 내역에서 참여자들이 나눠 낼 금액을 줄여주는 지원금. 소비 몫의 송금과 구분한다. | `Contribution` |
| **항목별 찬조금 적용** | 찬조금 중 특정 비용 항목에 적용하기로 정한 금액과 근거. | `ContributionAllocation` |
| **영수증** | 결제 금액과 품목을 확인하는 증빙 자료. OCR 추출 결과 자체와 구분한다. | `Receipt` |
| **비용 항목** | 한 결제 내역 안에서 누구에게 어떤 기준으로 나눌지 구분하는 비용. 식사비·술값 등이 해당한다. | `Item` |
| **비용 나누는 기준** | 특정 비용 항목을 누가 어떤 방식으로 나눠 낼지 정한 기준. | `SplitRule` |
| **개인별 부담 조정** | 특정 사람과 비용 항목에 적용하는 부담 제외, 합의 소비 몫 또는 대신 부담 조건. | `ItemException` |
| **항목별 개인 부담액** | 한 사람이 한 비용 항목에서 최종 부담하는 금액과 근거. 먼저 결제한 사람의 본인 몫도 포함한다. | `Allocation` |
| **송금 요청 내역** | 특정 결제 내역에서 누가 먼저 결제한 사람에게 얼마를 보내야 하는지와 처리 상태. | `SettlementResult` |
| **입금 확인 기록** | 특정 송금 요청에 대응시킨 입금액과 담당자의 대조·확인 기록. 확인 대기 기록도 포함한다. | `PaymentRecord` |
| **정산 재안내** | 송금 요청의 입금 여부를 재확인하거나 정산을 다시 안내하는 개인 메시지 또는 기존 서비스 알림 기록. | `ReminderMessage` |

## 2. 계산 방식과 개인별 부담 조정

| 대표 용어 | 뜻 | 이전 값 |
|---|---|---|
| **남은 금액 똑같이 나누기** | 찬조금과 제외 대상을 반영하고, 합의 소비 몫을 먼저 배정한 뒤 잔액을 나머지 대상자에게 균등 분담한다. | `equal` |
| **사람별 금액 정하기** | 확인된 사람별 소비 금액을 사용한다. 소비 몫의 합계는 찬조금 뺀 항목 금액과 같아야 한다. | `explicit_amount` |
| **이 항목은 부담 안 함** | 해당 사람을 해당 비용 항목의 분담에서 제외한다. 다른 항목까지 제외하지 않는다. | `exclude` |
| **이 항목의 내 몫 정하기** | 해당 사람의 이 항목 소비 몫을 합의 금액으로 정한다. 추가액이나 차감액이 아니다. | `fixed_amount` |
| **다른 사람이 대신 내기** | 기본 소비 몫을 계산한 다음, 확인된 다른 사람이 그 몫을 인수한다. 비용이 없어지는 것이 아니다. | `covered_by_other` |

**주의:** ‘이 항목의 내 몫 정하기’는 추가액·차감액을 지정하는 것이 아니다. 본인의 소비 몫을 합의한 금액으로 정한다. 이후 다른 사람 몫까지 대신 내면 최종 부담액은 더 커질 수 있다.

## 3. 금액 속성 용어 정의

모든 금액의 단위는 원이다. 같은 ‘금액’이어도 원래 결제액·소비 부담·송금 요청·입금 기록은 구분한다.

| 속한 개념 | 쉬운 속성명 | 뜻 | 이전 속성 |
|---|---|---|---|
| 결제 내역 | **결제한 총금액** | 사용자가 확인한 원래 결제 총액. 찬조 적용 전 금액을 보존한다. | `Expense.total_amount` |
| 결제 내역 | **찬조금 뺀 결제 금액** | 결제한 총금액에서 확정된 항목별 찬조금 적용액을 뺀 금액. | `Expense.distributable_amount` |
| 모임 차수 | **이 차수의 총결제액** | 해당 차수에 속한 유효 결제 내역의 총금액 합계. | `SettlementRound.total_cost` |
| 찬조금 | **찬조금 총액** | 이 결제 내역에 적용하기로 정한 찬조금 원액. | `Contribution.amount` |
| 항목별 찬조금 적용 | **이 항목에 적용할 찬조금** | 찬조금 중 이 비용 항목에 적용하는 금액. | `ContributionAllocation.amount` |
| 영수증 | **영수증에서 읽은 총금액** | 영수증에서 읽어 기록한 총액. 사용자가 확인한 결제 총액과 대조한다. | `Receipt.recorded_total_amount` |
| 비용 항목 | **항목 금액** | 비용 항목의 합계 금액. 단가나 개인 부담액과 구분한다. | `Item.amount` |
| 비용 항목 | **찬조금 뺀 항목 금액** | 항목 금액에서 이 항목에 적용한 확정 찬조금을 뺀 금액. | `Item.distributable_amount` |
| 개인별 부담 조정 | **이 항목의 합의 소비 몫** | 증감분이 아닌 본인의 합의 소비 몫. 다른 사람 몫을 인수하면 최종 부담액은 커질 수 있다. | `ItemException.fixed_amount` |
| 항목별 개인 부담액 | **이 항목에서 내가 부담할 금액** | 찬조·부담 조정·대신 부담·잔여 원 처리를 반영한 개인의 최종 항목 부담액. | `Allocation.amount` |
| 송금 요청 내역 | **이 결제자에게 보낼 금액** | 해당 결제 내역에서 돈을 보낼 사람의 항목별 최종 부담액 합계. 결제자 본인에게는 청구하지 않는다. | `SettlementResult.amount_due` |
| 입금 확인 기록 | **이 송금 요청에 대응시킨 입금액** | 하나의 송금 요청에 대응시킨 입금액. 실제 송금 한 건의 전체 금액과 항상 같지는 않다. | `PaymentRecord.amount` |

## 4. 관계를 문장으로 읽기

총무·결제자·부담자·찬조자는 별도 사람 유형이 아니라 참여자가 맡는 역할이다.

| 출발 개념 | 관계 | 연결 대상 | 이전 관계 |
|---|---|---|---|
| 참여자 | 소속 모임 정산 | 모임 정산 | `Participant.belongs_to` |
| 모임 정산 | 연결된 참여자 | 참여자 | `SettlementSession.has` |
| 모임 정산 | 정산 담당자 | 참여자 | `SettlementSession.coordinated_by` |
| 모임 정산 | 포함된 모임 차수 | 모임 차수 | `SettlementSession.contains` |
| 모임 정산 | 기록된 결제 내역 | 결제 내역 | `SettlementSession.records` |
| 모임 차수 | 소속 모임 정산 | 모임 정산 | `SettlementRound.belongs_to` |
| 모임 차수 | 차수별 참석 기록 | 차수별 참석 기록 | `SettlementRound.has` |
| 모임 차수 | 이 차수의 결제 내역 | 결제 내역 | `SettlementRound.contains` |
| 차수별 참석 기록 | 참석한 사람 | 참여자 | `RoundParticipation.participant` |
| 차수별 참석 기록 | 참석한 차수 | 모임 차수 | `RoundParticipation.in_round` |
| 결제 내역 | 소속 모임 정산 | 모임 정산 | `Expense.belongs_to` |
| 결제 내역 | 결제가 발생한 차수 | 모임 차수 | `Expense.in_round` |
| 결제 내역 | 먼저 결제한 사람 | 참여자 | `Expense.paid_by` |
| 결제 내역 | 결제를 확인할 영수증 | 영수증 | `Expense.supported_by` |
| 결제 내역 | 포함된 비용 항목 | 비용 항목 | `Expense.contains` |
| 결제 내역 | 적용할 찬조금 | 찬조금 | `Expense.funded_by` |
| 찬조금 | 찬조금을 적용할 결제 내역 | 결제 내역 | `Contribution.for_expense` |
| 찬조금 | 찬조한 사람 | 참여자 | `Contribution.contributed_by` |
| 찬조금 | 항목별 찬조금 적용 내역 | 항목별 찬조금 적용 | `Contribution.applied_through` |
| 항목별 찬조금 적용 | 가져온 찬조금 | 찬조금 | `ContributionAllocation.from_contribution` |
| 항목별 찬조금 적용 | 찬조금을 적용할 비용 항목 | 비용 항목 | `ContributionAllocation.to_item` |
| 영수증 | 증빙하는 결제 내역 | 결제 내역 | `Receipt.supports` |
| 영수증 | 확인할 수 있는 비용 항목 | 비용 항목 | `Receipt.documents` |
| 비용 항목 | 소속 결제 내역 | 결제 내역 | `Item.belongs_to` |
| 비용 항목 | 비용 나누는 기준 | 비용 나누는 기준 | `Item.allocated_by` |
| 비용 항목 | 적용할 개인별 부담 조정 | 개인별 부담 조정 | `Item.has_exception` |
| 비용 항목 | 적용할 항목별 찬조금 | 항목별 찬조금 적용 | `Item.has_contribution_allocation` |
| 비용 나누는 기준 | 나눌 비용 항목 | 비용 항목 | `SplitRule.for_item` |
| 비용 나누는 기준 | 나눠 낼 기본 대상자 | 참여자 | `SplitRule.applies_to` |
| 비용 나누는 기준 | 계산된 개인 부담액 | 항목별 개인 부담액 | `SplitRule.produces` |
| 개인별 부담 조정 | 부담을 조정할 비용 항목 | 비용 항목 | `ItemException.applies_to` |
| 개인별 부담 조정 | 부담을 조정할 사람 | 참여자 | `ItemException.affects` |
| 개인별 부담 조정 | 대신 내는 사람 | 참여자 | `ItemException.covered_by` |
| 항목별 개인 부담액 | 부담할 비용 항목 | 비용 항목 | `Allocation.for_item` |
| 항목별 개인 부담액 | 최종 부담할 사람 | 참여자 | `Allocation.assigned_to` |
| 항목별 개인 부담액 | 적용한 비용 기준 | 비용 나누는 기준 | `Allocation.based_on` |
| 송금 요청 내역 | 송금 요청의 결제 내역 | 결제 내역 | `SettlementResult.for_expense` |
| 송금 요청 내역 | 돈을 보낼 사람 | 참여자 | `SettlementResult.debtor` |
| 송금 요청 내역 | 돈을 받을 사람 | 참여자 | `SettlementResult.creditor` |
| 송금 요청 내역 | 근거가 되는 항목별 부담액 | 항목별 개인 부담액 | `SettlementResult.based_on` |
| 송금 요청 내역 | 연결된 입금 확인 기록 | 입금 확인 기록 | `SettlementResult.has` |
| 입금 확인 기록 | 대응하는 송금 요청 | 송금 요청 내역 | `PaymentRecord.for_result` |
| 입금 확인 기록 | 입금을 확인한 담당자 | 참여자 | `PaymentRecord.checked_by` |
| 정산 재안내 | 다시 안내할 송금 요청 | 송금 요청 내역 | `ReminderMessage.for_result` |
| 정산 재안내 | 안내를 받는 사람 | 참여자 | `ReminderMessage.recipient` |
| 정산 재안내 | 안내를 보내는 사람 | 참여자 | `ReminderMessage.sender` |

## 5. 상태와 기록 속성

| 대상·속성 | 상태값 |
|---|---|
| 모임 정산 · 모임 정산 상태 | 초안 / 요청됨 / 완료 |
| 결제 내역 · 결제 내역 검토 상태 | 검토 필요 / 검토 확정 / 제외 |
| 찬조금 · 찬조금 확정 상태 | 확인 필요 / 확정 |
| 비용 나누는 기준 · 비용 기준 확정 상태 | 확인 필요 / 확정 |
| 개인별 부담 조정 · 부담 조정 확정 상태 | 확인 필요 / 확정 |
| 송금 요청 내역 · 송금 요청 처리 상태 | 초안 / 요청됨 / 완료 |
| 송금 요청 내역 · 입금 확인 상태 | 입금 미확인 / 입금 확인 완료 |
| 송금 요청 내역 · 재안내 처리 방식 | 미정 / 개인 재안내 / 기존 서비스 알림만 사용 |
| 입금 확인 기록 · 송금 수단 | 정산 서비스 / 계좌이체 |
| 입금 확인 기록 · 입금 대조 상태 | 대조 대기 / 담당자 대조 확인 |
| 정산 재안내 · 재안내 수단 | 개인 메시지 / 기존 서비스 알림 |
| 정산 재안내 · 발송 확인 상태 | 예정 / 발송 확인 |

‘입금 확인 기록’에는 대조 대기 기록도 포함된다. 기록이 있다는 것만으로 실제 입금 확인이 끝난 것은 아니다. 송금 요청의 ‘입금 미확인’ 역시 실제 미입금을 뜻하지 않는다. 재안내의 ‘발송 확인’은 실제 발송을 확인한 경우에만 기록한다.

금액 외 속성도 YAML에서 쉬운 이름과 `definition`을 제공한다. 원본 단서·합류와 이탈·비용 발생·조정 이유·송금 가능 시점은 사용자가 확인한 내용만 남긴다. 정확한 시각이나 원문을 모르면 임의로 채우지 않는다.



## 6. 핵심 구분과 검증 원칙

- 결제 내역은 실제 비용 기록, 영수증은 증빙, 비용 항목은 대상·기준을 나누는 비용 단위다.
- 차수별 참석 기록만으로 차수 전체 부담을 제외하거나 시간 비례 계산하지 않는다.
- 비용 나누는 기준은 입력 합의이며 항목별 개인 부담액은 그 기준을 적용한 결과다.
- 개인의 비용 부담과 실제 송금액을 구분한다. 먼저 결제한 사람의 본인 몫은 송금 요청하지 않는다.
- 찬조금 총액과 항목별 적용액을 구분한다. 찬조 여부만으로 소비 부담 대상을 제외하지 않는다.
- 비용 항목별 개인 부담액 합계 + 확정 찬조 적용액은 항목 금액과 같고, 항목 합계는 결제한 총금액과 같아야 한다.
- 모호하거나 충돌하는 기준, 미확정 찬조금, 미검토 결제가 있으면 송금 요청을 확정하지 않는다.
- 소액을 청구하지 않아도 비용을 없애지 않는다. 대신 부담한 사람과 산출 근거에 남긴다.
- 정확한 계산 순서·관계 수·선택 속성·완료 조건은 YAML 정의와 하단 검증 제약을 따른다.
