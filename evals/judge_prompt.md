# Evals Judge 프롬프트 — 현재 비활성 (v0, 설계 후보)

> **현재 v1 Evals에서는 judge를 호출하지 않는다.** `evalset.jsonl`의 모든 `graders`는 `code`이며 `run_evals.py`는 코드 채점만 지원한다. `judge_version=not-used-code-only`로 기록한다. 이 파일이 존재한다고 judge 평가가 실행되었다는 뜻은 아니다.

## 사용하지 않는 이유

현재 MVP 평가 대상은 `RequestContext`의 사람·금액·항목·분담 예외, 영수증의 품목/총액, 구조화 출력 규칙이다. 객관적으로 판정 가능하므로 `LLM-as-a-Judge`보다 스키마·코드 비교를 우선한다.

## 후속 judge 후보: 정산 안내 문구의 근거·관계 적절성

후속 `NOTICE1` 기능을 구현할 경우 다음 기준을 judge 프롬프트로 정식 버전 관리한다.

- c1 숫자 충실성: 확정 계산의 금액/수취인/계좌가 왜곡되지 않았는가 (가능하면 코드 검증 우선)
- c2 관계별 말투: 사용자가 명시한 친구·직장 동료 관계에 부합하는 문장인가
- c3 비강압성: 상대에게 모욕적·위협적 표현이 없는가
- c4 상태 충실성: 실제 입금 미확인 상태를 무조건 미입금이라고 단정하지 않았는가

검증: 먼저 **실제 출력 20~30개를 사람이 judge 출력 없이 채점**하여 `evals/judge_labels.jsonl`로 남긴다. 그런 다음 judge 일치율이 80% 이상인지 확인한다. 현재 사람 라벨이 없으므로 judge 점수는 실행하거나 발표하지 않는다.
